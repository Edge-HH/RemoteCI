# Android 系统日历同步

Android 客户端与网页端一样提供两种互相独立的系统日历，入口在「账号与设置 → 系统日历」，也可在课表页直接操作：

- **我的日程**：「课表 → 我的日程」点击「导入日程」。自己的任教课程和自定义课程写入「RemoteCI 我的日程」本地日历。
- **班级课表**：「课表 → 本班课表」点击「同步课表」，多班级账号在对话框中选择班级。所选班级的未来七日课表写入「RemoteCI 班级名」本地日历，之后在应用中切换查看的班级不影响该日历。改选其他班级时日历随之改名，原班级未结束的课程会被删除，已结束事件保留。

首次需授予日历读写权限，再选择提醒时间和是否自动同步，由系统日历应用发送提醒。默认课前 10 分钟，可改为开始时、提前 5、15 或 30 分钟；两种日历分别设置。

启用自动同步后，打开课表页或系统日历页时每分钟检查更新；应用未打开时使用系统后台任务，约每 15 分钟同步一次。后台实际执行时间受联网状态、省电策略和系统调度影响。已导入事件的提醒由系统日历管理，不需要 RemoteCI 持续运行。请保持该日历可见，并允许系统日历应用发送通知。

再次导入会更新已有课程。我的日程以日期、班级、节次识别，班级课表以绑定班级、日期、节次识别；自定义课程每周重复，以课程 ID 与日期识别每一次课，修改名称或时刻会更新这些事件。课程名称、时间、班级地点变化会更新日历，取消的未结束课程会删除，已结束事件保留。同步范围仅包含 RemoteCI 导入的事件。我的日程的课程时间优先使用服务端给出的绝对时间或班级时区，旧服务端缺少时区时回退到手机时区；班级课表（`GET /api/schedule`）不含时区，按手机时区换算。

这是从 RemoteCI 到系统日历的单向同步。修改课程请在 RemoteCI 进行；直接在系统日历修改导入事件后，后续同步会恢复为 RemoteCI 中的内容。独立添加到日历的事件不会被同步管理。每次成功导入都会按照当前设置更新课前提醒。

关闭自动同步后仍可手动导入，已有事件及其提醒保留。退出登录会停止自动同步；切换账号或服务器后需为新身份重新导入，旧日历不会被改写。

权限被拒绝、设备没有日历服务、服务器不可达、日程格式无效、班级暂无课表或已失去该班级访问权时，界面显示失败原因，保留已有日历事件。日历写入采用批量事务，避免事件写入成功但提醒缺失。

验证命令：

```powershell
cd android
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
```

设备验证时依次检查（两种日历各一遍）：首次授权和导入、班级课表改选班级、再次导入无重复、修改课程名称及时间、取消未来课程、修改提醒提前量、关闭自动同步、退出登录、重启后后台同步、拒绝和撤销日历权限。系统提醒需在安装有日历应用的设备上验证。
