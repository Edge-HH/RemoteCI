# 0002 任课冲突只警告，确认后可继续

- 状态：已采纳（2026-10-24）
- 范围：换课申请的提交、预检与审批

## 背景

跨班换课后，某位老师可能同一时间要在两个班上课。原先换课只按节次序号匹配，不比较时间，各班时间表不同时既会漏报也会误报；也没有任何提示。

但同一时间出现在两个班并不总是错误：合班上课、同一位老师带两个班的自习或活动课都是合理的安排。

## 决策

- 按真实上下课时间判断重叠，不比较节次序号；本次换课腾出的课位不算冲突，没有时间的课跳过。插件从未同步过的班级按档案推算课表参与检查。
- 任课冲突是**需要确认的警告**，不是硬性拦截：未确认时服务端返回 409 `SWAP_CONFLICTS` 并列出冲突，申请人或审批人确认（`acknowledgeConflicts: true`）后照常执行，确认过的冲突记录在申请中。
- 同一节课还有其他待审批申请也按同样方式确认（这次生效后它们会失效）；课位当天已调整过只作提示。
- 审批时重新检查：提交时确认过不代表审批时不再提示，审批人要自己确认。

## 后果

- 合班等合理安排不需要管理员介入，误报也不会阻塞换课。
- 客户端需要处理 409 `SWAP_CONFLICTS`：WebUI 提交前预检并弹出确认，审批遇到冲突时在卡片上列出并提供“仍然通过”；安卓弹窗确认后带确认标记重发；一次性确认链接页面列出冲突并要求勾选。旧版客户端只能看到 409 的说明文字，文字本身提示到新版 App 或网页确认。
