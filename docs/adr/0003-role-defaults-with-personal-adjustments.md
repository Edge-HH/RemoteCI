# 0003 权限 = 角色默认 + 个人调整；功能拆成独立权限

- 状态：已采纳（2026-10-31）
- 范围：账号与角色的权限模型、WebUI 角色与人员编辑器、各控制与管理功能的鉴权

## 背景

原先账号的个人权限是“附加权限”：有效权限 = 角色默认权限 ∪ 个人附加，只能加不能减，编辑器里也看不出一个人到底有哪些权限。大量功能没有独立权限：音量跟电源、清除通知跟发送通知、主界面文件跟主界面显隐绑在一起；远程终端、插件管理、软件升级、ClassIsland 启停、守护管理都借用“人员管理”并另外写死为系统管理员；电子班牌、操作记录、课时统计、本班档案与插件设置写死为“本班班主任”；系统级页面（班级管理、档案库、调休、设备状态、批量控制、自动化等）全部写死为系统管理员。

## 决策

- 角色设置一组默认权限；账号的个人设置记录为相对角色的**新增与收回**，有效权限 = 角色默认 + 新增 − 收回。编辑器按分组列出全部权限并勾选当前拥有的项，保存时换算为新增与收回；与角色默认不同的项标为“已新增 / 已收回”，可一键恢复。存差异而不是完整快照，是为了让角色默认权限的修改继续作用于未单独调整的人，并让同一套调整在各班级按班内角色生效。
- 权限分两类：**班级权限**沿用 `UserPermissions`（按各班的班内角色计算，随命令下发插件做纵深防御），新增第 16–30 位承载拆出的功能；**系统管理权限**是新的 `ManagementPermissions`，只按全局角色计算、只在服务端使用。`UserPermissions` 保持 32 位整数，因为第三方扩展的公开接口 `IRemoteCiExtension.RequiredPermission` 使用该类型，改成 64 位会破坏已编译的扩展。
- “班级自治策略”不再单独存在：它就是内置“班主任”角色的“班级信息”“刷新课表”权限；旧接口读写映射到该角色。
- 非管理员通过“人员管理”或“角色配置”修改权限时只能授予自己拥有的权限；班级管理不能授予班内“管理员”角色。系统配置、服务端更新与备份、管理员账号本身仍只属于系统管理员。
- 升级迁移按原有权限补齐拆出的新权限（例如有电源控制的补音量），内置班主任补齐原先按身份开放的功能，升级后行为不变。

## 后果

- 每个功能都能单独授予或收回，例如给“教务处”角色开放学期与调休、档案库而不必给系统管理员。
- 旧插件仍按旧权限表复核：服务端发往插件的命令在发起人具备新权限时补上旧插件认的位；旧插件对远程维护另有“仅系统管理员”检查，委派给非管理员需要先升级插件。
- 旧客户端更新账号时不带收回与系统管理权限字段，服务端保持原值，不会清空。
- `UserPermissions` 的 31 个可用位已用完，以后新增班级权限需要另起位集。
