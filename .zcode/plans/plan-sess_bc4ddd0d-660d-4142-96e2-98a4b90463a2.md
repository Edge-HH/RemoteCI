# 老师（Teacher）角色实现计划

## 背景结论（探索确认）

- 课表数据在教室端 ClassIsland 档案中（`Subject.TeacherName` 自由文本），由插件推送 7 天 `ScheduleBundle`，服务端仅内存缓存（`IStateStore`），**无持久化课表**。
- 按你确认的三个决定：**复用显示名（DisplayName）做绑定**、**地点只显示班级名**、**科目教师分配仅 Web 管理端**。因此**无需任何数据库列迁移**。
- 角色体系已有内置角色种子先例（班管理员 `ClassAdministratorId`，`BootstrapAsync` 幂等种子 + 改中文名），老师角色完全照此模式，无需迁移。
- 权限无需新增位：复用 `SendNotifications(8)`、`SendVoiceMessages(512)`、`ChangeDisplayName(1024)`、`ManageSchedule(16)`。
- 关键链路：`ClassAccessService.GetAccessibleClassesAsync` 是 `/api/me`、`/api/me/classes`、Web 页面、授权镜像的共同上游——在该服务加入“按名字绑定的任教班级”后全链路自动生效。但 `IdentityCoordinator.CreateSyncAsync`（推送插件 LAN 鉴权镜像）单独从 `ClassMemberships` 构建，需要单独处理，否则 LAN 直连时老师发通知/语音会被插件拒绝。

## 1. shared/RemoteCI.Shared（协议层，先做）

`Protocol.cs`：
- `CommandKind` 追加 `SetSubjectTeacher = 21`（注释：设置班级科目的授课教师，写入 ClassIsland 档案）。
- `CommandPermissions.Required`：`SetSubjectTeacher => ManageSchedule`。
- `RemoteCiCapabilities`：新增 `ScheduleSubjectTeacher = "schedule.subject-teacher"`（加入 `Current`，**不进 Baseline**）+ `ChineseName`（“设置科目教师”）+ `Required` 映射。

`Models/ScheduleModels.cs`（全部可空、向后兼容）：
- `CourseEntry` + `teacher`；`SubjectEntry` + `teacher`（插件从 `Subject.TeacherName` 填充）。
- 新 `SubjectTeacherRequest { subjectId, teacherName }`（teacherName 空 = 清除）。
- 新 `MyScheduleResponse { fromDate, generatedAt, days }` / `MyScheduleDay { date, items }` / `MyScheduleItem { classId, className, courses: CourseEntry[] }`。

`Models/AuthModels.cs`：`UserProfile` + `roleKind`（可空 int，服务端填 `(int)role.Kind`，供手机端免受角色改名影响地识别“老师”）。

## 2. plugin/RemoteCI.Plugin

- `ScheduleCatalog.cs`：`SubjectEntry`/`CourseEntry` 填充 `Teacher`（来自 `Subject.TeacherName`）。revision 计算不变（教师名是元数据，不破坏现有 expectedRevision 流程）。
- 新命令处理：`CommandHandler` 加 `SetSubjectTeacher` 分支——按 `subjectId` 找到档案科目、写 `TeacherName`、保存档案，随后走与 `ChangeSchedule` 相同的“变更后重推 bundle”路径；能力协商上报 `schedule.subject-teacher`。
- `WebSocketHub.ValidateCommandParameters`（服务端）：校验 `subjectId` 非空、`teacherName` ≤ 100 字符。

## 3. server/RemoteCI.Server

**角色种子**（`Data/Entities.cs` + `Services/IdentityCoordinator.cs`）：
- `AccountRoleKind.Teacher = 5`；`AccountRole.TeacherId = 55555555-5555-5555-5555-555555555555`。
- `TeacherDefaultPermissions = ViewCurrentCourse | SendNotifications | SendVoiceMessages | ChangeDisplayName`（`ChangeDisplayName` 是“老师填写姓名完成绑定”的必要权限；其余权限管理员可在角色设置/人员设置中追加，且追加后自动作用于所有任教班级——见下）。
- `BootstrapAsync`：照班管理员先例 `INSERT OR IGNORE` + `ExecuteUpdate` 改名为“老师”、设 Kind/DefaultPermissions（同时覆盖全新库与升级库）。

**绑定服务**（新 `Services/TeacherBindingService.cs`，注入 `AppDbContext` + `IStateStore`）：
- 静态匹配器：`Match(姓名, 教师字段)` = trim 后完全相等，或教师字段按 `、 , ， / ; ；` 分词后任一词元完全相等（空名不匹配）。
- `GetTaughtClassesAsync(姓名)`：遍历 `db.Classrooms`（少量，内存排序），逐班取 `stateStore.GetLatestSchedule`，筛出匹配课程；`BuildMyScheduleAsync(姓名)` 聚合成 `MyScheduleResponse`（按日期、班级、节次排序）。

**按班权限接入**（`Services/ClassAccessService.cs`，注入 `TeacherBindingService`）：
- `GetEffectivePermissionsAsync`：无成员关系时，若该班是用户的“任教班级”→ 返回 `EffectiveForMembership(role, 全局角色默认权限, granted)`——即老师角色的默认权限（可在角色设置中追加）+ 个人授予（人员设置），精确满足“其他权限可在角色设置或人员设置中附加”。
- `CanAccessAsync` / `GetAccessibleClassesAsync` / `GetAccessibleClassIdsAsync`：并入任教班级（`RoleName` 取用户全局角色名，非成员班级同样可见可切换）。管理员路径不动。
- `IdentityCoordinator.ToProfileAsync` 已有 `RoleName`/填 `roleKind` 一行；`UserProfile.Permissions` 不变。

**授权镜像**（`IdentityCoordinator.CreateSyncAsync`）：对该班级额外纳入“名字匹配该班课表且全局角色 Kind==Teacher 的启用账号”，有效权限 = 全局角色默认 + 个人授予；`HandleScheduleSyncAsync` 保存新 bundle 前后对比该班“匹配教师集合”，变化时触发 `AuthorizationSyncService.SyncAsync`，保证 LAN 直连鉴权镜像及时更新。

**REST**（`Program.cs` + `docs/protocol.md`）：
- `POST /api/me/display-name` `{ displayName }`：复用 `IdentityCoordinator.ChangeDisplayNameAsync`（1–40 字校验、bump Version、触发同步），按现有 REST 鉴权要求 `ChangeDisplayName`。
- `GET /api/me/schedule`：`TeacherBindingService.BuildMyScheduleAsync(当前用户 DisplayName)`；管理员/无绑定返回空 days。

**Web 管理端**：
- `Pages/Schedule.cshtml(.cs)`：新增“科目教师”区（列出 bundle 科目+当前教师，每行输入框+保存）→ `OnPostSubjectTeacherAsync` 走页面现有命令下发路径发送 `SetSubjectTeacher`，页面权限仍是 `ManageSchedule`；`_ScheduleTable.cshtml` 课程格内以小字展示教师名。
- Users 页角色下拉自动出现“老师”，权限编辑器无需改。

## 4. android（手机端，包 `com.remoteci.mobile`）

- `data/Protocol.kt`：`CourseEntry`/`SubjectEntry` + `teacher: String? = null`；`UserProfile` + `roleName`/`roleKind` 可空字段 + `isTeacher` 助手；新增 `MyScheduleResponse/Day/Item` DTO。
- `data/AdminApi.kt`：`getMySchedule()`、`updateDisplayName(name)`（`UpdateDisplayNameRequest`）。
- `ui/SettingsScreens.kt` AccountScreen：新增“姓名”编辑项（预填 displayName → POST，成功后刷新本地 currentUser），教师身份下提示“与课表中的教师名一致即可自动关联自己的课程”；角色标签改用 `roleName`（老师账号显示“老师”）。
- `ui/HomeScreens.kt` ScheduleScreen：`user.isTeacher` 时顶部加「我的日程 / 本班课表」切换，默认“我的日程”——按天分组展示（班级名作分组头 + 每节：科目、教师、节次、起止时间），REST 拉取 + 空态文案（“未找到与你姓名匹配的课程…”）。通知/语音/班级切换无需改动（任教班级经服务端 classes 列表自动出现，按班权限门控已存在）。
- wearos 不在本次范围（协议改动均为可选字段，向后兼容）。

## 已知限制（写入 docs/protocol.md）

- 绑定基于内存中的最新课表缓存：服务端刚重启、班级插件尚未推送课表时，任教班级/我的日程为空，收到 bundle 后自动恢复。
- 同名教师会绑定到同名课程（ inherent 于按名匹配），建议使用完整姓名；必要时管理员可通过科目教师分配统一写法。
